# YUI Neko 小黑貓 UI 設計提案

日期：2026-10-14。範圍：語音浮窗、常用詞典、角色與 Logo 的使用規格。這是設計文件，未修改 App、未執行實機 UI 或辨識驗證。

## 1. 設計方向與已知基線

角色方向待使用者從三張概念板選擇，再統一 Logo、浮窗與動作素材。現在先確定操作架構；角色尚未定稿，概念板內所有詞條、時間與數字皆為示意。

選樣板順序：01 `01-soft-loaf.png`、02 `02-moonlit-familiar.png`、03 `03-ink-nap.png`，均位於本文件同一資料夾。圖中介面是靜態概念示意；操作規則及錯誤狀態以本文件提案為準。本輪交付供選擇角色，不開始 App 實作。

視覺氣質：安靜、慵懶、帶一點好奇心的小黑貓；圓潤輪廓、大眼與自然耳朵動作。可參考奇幻動畫的親和力與光影，角色保持原創。小尺寸以清楚的貓耳、頭型和眼睛建立辨識度，細毛與複雜光影不作為必要資訊。

| 項目 | 目前原始碼／文件可確認 | 本次提案 |
| --- | --- | --- |
| 詞典管理 | 已加入／候選／學習紀錄、搜尋、新增、單選編輯、啟停、釘選、刪除 | 保留流程，改成清楚的清單與選中編輯區 |
| 候選 | 本機修正候選須確認，才成為正式詞條；可修改、拒絕 | 明確區分「儲存候選」與「確認加入」 |
| 詞典提示 | 最近請求的納入／額度未納入／停用資訊與提示次數 | 清楚呈現「有提供提示」，不得改稱命中率或準確率 |
| 自動學習 | 文件記錄離線測試與建置通過；跨 App AX 修正觀察與辨識效果待實機驗證 | 狀態及未建立候選原因常駐可查，不把學習描述成一定成功 |
| 語音浮窗 | 使用者截圖為黑色膠囊、取消、聲波、完成按鈕 | 加入角色、完整狀態文案與低干擾動作 |
| 短語音品質檢查 | PRODUCT_SPEC.md 列為需求，不能視為已完成 | 下列不確定結果流程須與品質判定一起實作 |
| iPhone 同步 | 此分支尚未整合 | 顯示「僅儲存在這部 Mac」，不放已同步標章 |

既有資料限制：正式詞條最多 200 筆，每詞最多 40 字；候選紀錄最多 500 筆、每段最多 40 字；完整提示上限為 200 UTF-8 bytes，基礎指示也占額度。學習觀察最多兩分鐘，僅限支援的本機已驗證貼入範圍。

## 3. 語音輸入浮窗

### 結構與位置

- 沿用黑色膠囊，建議約 300 × 68 pt。由左至右為「取消」、小黑貓、聲音強弱、結束錄音；狀態文字使用固定高度區，變更狀態不讓按鈕跳位。
- 貓咪可趴在膠囊上緣，耳朵與尾巴超出視覺邊界的區域不可攔截滑鼠事件；完整視窗範圍仍須計入避讓。
- 預設放目前螢幕下方、工作區邊界內；能取得輸入框／游標位置時避開該區與輸入法候選窗。無法取得時使用上次位置；提供獨立拖曳區調整位置。
- 錄音與處理時採不搶輸入焦點的浮窗。切換狀態及播放動畫不得讓其他 App 失去焦點，也不得在送出後把文字貼往不同的目標。
- 聲波只反映實際麥克風音量，不代表辨識進度或準確度。不得播放預製波形假裝正在收音；貓咪動作與聲波功能分開。
- 右側勾號在錄音時的輔助標籤固定為「結束錄音並辨識」，不是「確認辨識內容」。無音訊可處理時停用並說明。

### 狀態與精確文案

| 狀態 | 畫面文案 | 主要操作／轉移 | 貓咪與聲波 |
| --- | --- | --- | --- |
| 錄音中 | **正在聽你說**；次要顯示實際錄音時間 | 左「取消錄音」；右「結束錄音並辨識」 | 進入時抬耳一次；真實音量波形；保持安靜注視 |
| 處理中 | **正在辨識…** | 「取消」；重複送出停用；成功、未清楚辨識或連線失敗後轉移 | 聲波停止，改小型進度指示；耳朵回到休息位置；不顯示虛構百分比 |
| 已貼入 | **已輸入** | 僅收到貼入成功事件後進入；約 1.2 秒後收起 | 閉眼輕點頭一次，不跳躍 |
| 只複製成功 | **已複製，請貼上** | 「關閉」；不能顯示「已輸入」 | 靜態貓臉與複製圖示 |
| 未清楚辨識 | **未清楚辨識到語音**；「可以靠近麥克風，再說一次。」 | 「重新錄音」／「關閉」；不自動貼入，不自動循環重試 | 小幅偏頭一次，沒有責備表情或聲音 |
| 有文字但結果待確認 | **這段內容可能不準確**；「請確認後再使用。」 | 「查看內容」開啟結果預覽；預覽提供「確認使用」／「重新錄音」／「取消」 | 靜態專注表情；不得以成功動作暗示內容可靠 |
| 連線失敗 | **暫時無法連線**；「檢查網路後，再試一次。」 | 「重試」／「取消」；僅使用者操作才重送 | 靜態貓咪＋連線圖示，無循環沮喪動畫 |
| 已取消 | 不顯示成功訊息 | 結束本次工作並收起；晚到的回應不得貼入 | 不播放完成動作 |

「連線失敗」只用於可確認的網路錯誤；權限、憑證或服務錯誤須使用實際原因與對應操作，不全部歸類成網路問題。重試是否可重用本次音訊取決於實際可用資料；若音訊已釋放，操作須改成「重新錄音」。不得為此預設永久保存錄音。

不確定結果的完整文字只出現在使用者主動開啟的本次預覽；不可自動寫入學習紀錄。鍵盤操作以既有快捷鍵設定為準，避免臨時新增會攔截其他 App 輸入的全域按鍵。

## 4. 常用詞典畫面

### 版面

建議視窗 900 × 680 pt，可縮至約 640 × 440 pt。頂部顯示小型靜態貓 Logo、標題「常用詞典」、說明「把常用名稱加入詞典，讓下次辨識有更多提示。」及「新增詞條」。

主區採「清單＋選中編輯區」，上方分頁為「已加入」「待確認」「學習紀錄」。對應既有資料中的已加入、候選與候選歷史。清單約占 55%；窄視窗以按下「編輯」開啟同樣欄位的面板，不擠壓原辨識與修正詞。

搜尋提示為「搜尋詞條或原辨識」。底部固定顯示「已加入 {n}／200　待確認 {m}」及「僅儲存在這部 Mac」。學習狀態使用一行摘要，可展開原因；不得讓長錯誤訊息把清單推出視窗。

### 已加入與選中編輯

清單欄位：詞條、啟用、釘選、提示次數。單選後整列淡綠底，編輯區標題「編輯詞條」，顯示以下欄位：

- 「詞條」文字框與「{目前字數}／40」；空白、超長或重複錯誤就地說明，不只彈出通用錯誤。
- 「啟用」及說明「啟用的詞條會依提示額度選用。」
- 「優先使用（釘選）」及說明「釘選會提高提示優先順序，仍受容量限制。」
- 最近提示狀態使用已知資訊顯示「已納入提示」「因提示額度未納入」「已停用」或「尚無提示紀錄」。若資料只能判斷未納入，不猜原因。
- 操作「儲存變更」「取消」與次要「刪除詞條」。有未儲存內容時切換詞條，顯示「儲存變更後切換」「放棄變更」「繼續編輯」。

未選取時顯示「選擇左側詞條以查看或修改。」新增使用同一組欄位，標題「新增詞條」、按鈕「加入詞典」。儲存成功顯示「已儲存，下次辨識依提示額度選用。」

刪除對話框：「刪除『{詞條}』？」／「刪除後不再用於下一次辨識提示。」操作「刪除」「取消」。

### 待確認候選

每列顯示「原辨識 → 修正詞」、狀態「待確認」、來源「本機修正」及更新時間。選中後編輯區呈現：

| 欄位／操作 | 精確文案與行為 |
| --- | --- |
| 標題 | 「確認這個詞」 |
| 說明 | 「這是一次修正產生的候選，確認後才會加入詞典。」 |
| 唯讀欄位 | 「原辨識」「來源」「建立時間」 |
| 可編輯欄位 | 「修正詞」與 40 字上限；範例：原辨識「有意策略」，修正詞「有一策略」 |
| 儲存草稿 | 「儲存候選」；保持待確認，不加入提示 |
| 正式加入 | 「確認加入」；如有編輯先驗證並儲存候選，再確認加入；失敗時保留候選及原因 |
| 拒絕 | 「拒絕候選」；不加入詞典，歷史顯示「已拒絕」 |
| 完成提示 | 「已加入詞典，下次辨識依提示額度選用。」 |
| 詞典已滿 | 「詞典已滿（200 詞）。請先移除不需要的詞，再確認加入。」；候選保留 |

空狀態：「目前沒有待確認的詞。修正貼入的專有名詞後，支援的 App 可產生候選；你也可以手動新增。」這是條件式能力，不使用「我會自動記住你說的每一句話」。

### 學習紀錄與提示資訊

學習紀錄只顯示詞彙片段、來源類型、時間及「待確認／已加入／已拒絕／已移除」狀態，不顯示或儲存完整句子、完整逐字稿、錄音及安全欄位內容。「已移除」表示對應詞條已不在正式詞典。

「刪除紀錄」與「刪除詞條」分開命名。刪除已加入的歷史紀錄不等同刪除正式詞條；刪除已拒絕紀錄前說明「刪除後，相同修正可能再次成為候選。」

最近一次提示資訊使用可展開區塊，標題「最近一次辨識提示」，列出「已納入」「因提示額度未納入」「已停用」，並固定顯示：

> 提供提示不保證辨識命中。「提示次數」只代表詞條納入辨識請求的次數。

學習摘要優先呈現現有狀態與實際原因，例如「等待下一次本機語音輸入」「已建立候選，等待確認」「這次變更不像單一詞彙修正，可手動新增」。觀察不支援、換焦點、逾時、僅複製、容量已滿或資料讀取失敗均須可查；不得用「正在學習」掩蓋已停止的狀態。資料讀取失敗時保留原資料，不以空清單覆寫。

## 5. 貓咪動作與 Logo

| 動作 | 播放時機 | 長度／限制 |
| --- | --- | --- |
| 耳朵抖動 | 進入錄音、使用者點擊角色 | 約 350 ms，單次；連續點擊合併 |
| 慢眨眼 | 詞典開啟且閒置，或浮窗錄音較久 | 約 500 ms，兩次至少間隔 15 秒；不影響波形 |
| 輕搖尾巴 | 詞典閒置，角色完整可見時 | 約 1.5 秒；最多每 30 秒一次，不無限循環 |
| 搔癢 | 詞典持續閒置 45 秒以上 | 約 2 秒；每次開窗最多一次；輸入、捲動或選詞立即停止 |
| 點頭／閉眼 | 收到貼入成功，或詞條成功儲存 | 約 600 ms，單次；不遮蔽成功文案 |
| 偏頭 | 未清楚辨識到語音 | 約 400 ms，單次；錯誤文字保持清楚 |

不播放音效、不在使用者輸入途中跑過清單、不讓動作改變控制項位置。選中編輯時貓咪保持靜態；連線失敗、敏感結果預覽與儲存錯誤不播放嬉戲動作。非前景詞典窗停止所有非必要動畫。

設定「減少動態效果」預設跟隨 macOS；啟用後停用耳朵、尾巴、搔癢、位移及循環動畫，狀態以靜態貓咪、圖示與文字替換。音量提供簡單強弱指示，不使用彈跳或大幅縮放。所有狀態都有 VoiceOver 標籤，狀態變更只宣告一次，不逐秒朗讀時間或音量；使用者可關閉角色動畫而保留錄音資訊。

Logo 待角色選定後製作三個版本：完整角色、簡化貓頭、macOS 選單列單色模板。貓頭在 16／24／32 pt 仍能辨識；選單列不用細眼線表達錄音狀態，另加清楚的狀態標記。App 圖示、詞典標題與錄音浮窗共用頭型與眼睛比例，先交付靜態輪廓，再製作表情與動作素材。

## 6. 實作與驗收順序

1. 使用者選定角色方向與眼睛／頭型，再製作一致的 Logo 與靜態狀態素材。
2. 實作浮窗狀態文案、焦點保留、位置避讓與詞典選中編輯；先用靜態角色驗證完整流程。
3. 串接既有詞典／候選儲存及真實音量事件；不以示意數據冒充執行結果。
4. 對短語音不確定流程補齊實際品質判定與人工確認，再加入有限次動作及減少動態效果。
5. 在 TextEdit 與瀏覽器驗收：錄音不搶焦點；送出不擋輸入框；候選修改不直接入典；確認才入典；重啟後狀態一致；提示與命中分開；一般改寫不保存完整句子；縮小視窗、鍵盤、VoiceOver 與減少動態效果可用。

這些是後續驗收條件，本設計文件未完成以上實機驗收，也未證實辨識準確率提升。
