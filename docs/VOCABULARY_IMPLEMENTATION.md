# 詞典學習修正

2026-10-15 更新：修字已改為穩定後顯示六秒「不加入」提示，未取消即加入；下列九套測試與人工確認制為先前版本紀錄。最新行為及驗證見 [本次修復紀錄](NEIGHBOR_REPAIR_2026-10-15.md)。

狀態：本機實作完成，九套離線測試與 App 建置／嚴格簽章驗證通過；實機 AX 與辨識效果待驗證。

## 已查明的原因

- main 基線及第一批重構尚未包含本機未提交詞典，GroqDictationTranscriber 只送語言提示。
- 原本機的 showVocabularySuggestion 只顯示即時確認視窗，不保存候選；取消後沒有待辦清單。
- PasteCorrectionMonitor 需要 AX 可編輯元素、選取範圍、精確貼入內容及 AX 通知；多個 guard 靜默返回，使用者無法知道未啟動。
- 原詞典有 200 UTF-8 bytes 的完整提示上限，基礎指示也占額度；不是所有啟用詞條都能納入，原介面沒有顯示未納入原因。

## 範圍與順序

1. 從原目錄唯讀移植詞條格式、儲存、修正擷取及受限 AX 觀察器，保留穩定 UUID／revision／tombstone 與原儲存鍵，不移植 remote v2。
2. 增加獨立候選儲存，確認才成為正式詞條，拒絕、編輯、容量與錯誤狀態可見；不保存完整句子。
3. 管理視窗提供候選與已加入篩選、搜尋、修改、啟停、釘選與刪除；顯示學習與提示狀態。
4. 本機貼上成功發送事件後，啟動受限修正觀察；失敗或只複製時說明原因。不監看安全欄位、不觀察遠端送出。
5. 注入實際轉錄提示並記錄納入／未納入詞條；補流程與資料相容性測試，再完整建置。

風險：高，涉及 Accessibility 與本機既有詞典資料。原工作目錄及資料唯讀；測試一律使用隔離 UserDefaults。程式不安裝、不啟動、不存取真 Keychain。本批不更改 Groq 請求欄位、模型、版本或遠端線上協定。

人工驗證邊界：不同 App 的 AX 通知／範圍支援、實際修正擷取與模型辨識改善須實機驗證。提示使用不等同辨識命中。

## 已完成與驗證

- 沿用 `codex/neko-foundation-refactor`；原目錄 HEAD、分支、狀態、index／工作目錄差異與 28 個檔案 SHA-256 皆與改動前一致。
- `test-vocabulary-learning.sh` 驗證候選自動保存、重複抑制、修改、確認加入、拒絕與刪除紀錄、重開讀取、提示納入／停用／額度、容量滿時保留候選、舊 array／payload 格式、UUID 與刪除墓碑，以及損壞資料不覆寫。
- `test-all.sh` 九套離線測試通過，包含原 dictation 17 組情境；`build.sh` 編譯及嚴格簽章驗證通過。未呼叫真正 Groq API、未讀使用者 Keychain、未安裝或啟動新 App。
- 管理入口：選單列「詞典與學習狀態…」→ 已加入／候選／學習紀錄。候選需確認加入才納入提示；拒絕後不反覆提示，可刪除紀錄解除抑制。
- 學習限本機已驗證的貼入範圍，最多兩分鐘；換焦點或不支援 AX 範圍／通知時停止並說明。一般新增文字不建立候選，較長改寫與句子標點變更不直接加入詞典。
- 候選最多 500 筆紀錄、每段最多 40 字；滿時停止建立並提示清理。字典仍最多 200 詞、完整提示最多 200 UTF-8 bytes。提示次數只代表納入請求，不是模型命中率。
- 當詞典／候選資料無法解碼，保留原資料並顯示錯誤，避免以空清單覆蓋。維持原儲存鍵與同步資料格式，但未接入 v2 訊息及 iPhone 同步。

## 人工驗收

以 TextEdit 及瀏覽器實測：錄音貼入 → 將專有名詞修正 → 詞典候選出現 → 確認加入 → 下次提示顯示納入。再測安全欄位、焦點切換、只複製、兩分鐘逾時與不支援 AX 的 App。視窗與跨 App 觀察本輪僅編譯驗證，不能宣稱已確認實機自動學習或辨識改善。


## 2026-10-15 自動加入更新

最新使用者需求已將新修正詞改為預設自動加入：同一個已驗證貼入範圍內，停止編輯約 1.1 秒後顯示六秒「不加入」提示；滑鼠移上提示會暫停倒數；到期仍是相同修正且未拒絕才確認加入。舊候選仍保留手動確認入口。AX 通知缺失時使用受限輪詢；換目標、跨越範圍或不能驗證時停止。以上更新取代前文關於所有候選一律人工確認的舊流程說明。
